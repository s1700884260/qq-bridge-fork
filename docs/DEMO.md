# 30 秒演示怎么录

演示比 README 有用：别人只想知道「它到底能不能像人一样在群里说话」。下面这条 30 秒的分镜按
「一句话 + 一个能力」剪，不要念参数、不要展示终端。

## 分镜（约 32 秒）

| 秒 | 画面 | 旁白字幕 |
| --- | --- | --- |
| 0–4 | QQ 群聊界面，群友发「有人会写正则吗，这个匹配不上」 | 群友随口一问 |
| 4–8 | 机器人两秒内接话，给出真正能用的正则 | 它自己判断该不该接话 |
| 8–12 | 群友刷「哈哈哈」「.+1」「这是啥」 | 闲聊时它不吭声 |
| 12–16 | 字幕：本地小模型判定，闲聊不烧 token | —— |
| 16–21 | 群友「唱一个」→ 机器人发语音条（播放） | 真唱，不是念稿 |
| 21–25 | 群里发一张搜来的图（百度图源） | 会自己搜图 |
| 25–30 | 私聊：机器人发一段语音 + 表情包 | 私聊更放得开 |
| 30–32 | 结尾卡：项目名 + 仓库地址 + 「一键安装，详见 README」 | —— |

## 录制要点

- 用真机录（手机投影或 QQ 桌面版放大），不要录终端。
- 群里提前铺 2~3 条真实聊天，避免画面空。
- 录之前把 `socialV2.localTriage.enabled` 打开，冷启动会等十几秒，先发一条无关消息让模型预热。
- 语音条要让人听见（开着声音录），比任何文字都有说服力。
- 输出 1080×1920 竖版优先（贴吧/群/短视频都能发），文件小于 10MB。

### 录制前脱敏清单（重要）

视频一旦传到 Release 或贴吧，就是**公开且会被镜像/存档**的，删掉也不保证消失。录之前逐条确认：

- [ ] **群名、群号**改掉或打码（QQ 桌面版标题栏、群设置页、控制台左上角都会显示）
- [ ] **群成员昵称/头像**：用测试号或小号铺聊天，别录真人群的真实成员
- [ ] **你自己的 QQ 昵称**（机器人名里常带你的外号）+ **私聊窗口**
- [ ] 桌面文件名、任务栏图标、微信/其他聊天软件的**通知弹窗**
- [ ] 控制台里的 `config.json` 片段、`accessToken`、`baseUrl` 端口
- [ ] 视频**元数据**：手机录屏常带设备型号与拍摄时间，必要时先转码（`ffmpeg -i in.mp4 -map_metadata -1 -c copy out.mp4`）
- [ ] 别用带定位权限的相机 App 录制

> 已经公开的上游项目视频（README 里那个 `Derpyu520/qq-bridge` Release 链接）与你无关，不需要你上传任何文件；
> 只有**你自己新录**的演示才需要走这份清单。


## 配文（发帖直接用）

三份都写好了，按场景挑一段复制，**改掉括号里的占位符**再发。

### A. 贴吧 / 论坛（长一点，带技术取舍）

**标题**：把我的 DeepSeek 机器人塞进 QQ，跑了两个月的踩坑记录（开源）

**正文**：

> 折腾了两个多月，把 DeepSeek Harness 接进 QQ 的桥接项目，今天开源了：
> https://github.com/s1700884260/qq-bridge-fork
>
> 起因很简单：我想让 AI 以「群友」的身份待在群里，而不是每次都得手动敲一句。
>
> 但它不是「接上就能用」的：
>
> - **会乱接话**。默认每条群消息都唤醒模型，一个 200 人的群一天能耗掉几十块。最后加了本地小模型分流：
>   群消息先过本机 `qwen2.5:3b`（Ollama，约 40ms），判断「这条值不值得接」，闲聊直接不理，云端一次都不调。
> - **长会话重复计费**。上下文越长，每轮输入都要重发一遍，token 消耗是超线性的。改成超过阈值就自动开新会话 +
>   摘要接续之后，长期成本压下来一大截。
> - **会掉线**。DSH 每次重启端口都变，桥接就失联。现在桥接自己探测端口，外加只在 DSH 运行时才拉起的守卫进程。
> - **只会打字太无聊**。于是加了 Edge TTS 念任意文字、DiffSinger 真唱两句、本地表情包、百度搜图、搬博文。
>
> 现在它的日常是：群里有人提问才吱声，私聊随时在，群聊按点上下班；会发表情包，心情好了发条语音。
>
> 上游是 [Derpyu520/qq-bridge](https://github.com/Derpyu520/qq-bridge)（MIT），我这层是叠加的，`FORK.md` 里逐条列了改了什么。
> Windows 一键脚本：`install.ps1` → 打开 DSH → `start-qq-bridge.ps1`，出问题跑 `check.ps1` 自检。
>
> 需要自备 SnowLuma（QQ 协议端）+ DeepSeek API key。纯兴趣项目，有问题直接提 issue。

### B. 群聊 / 私聊转发（短，别刷屏）

> 把我的 DeepSeek 机器人接到了 QQ 上，现在它：
> · 群里有人提问才接话，闲聊一律不理（本地小模型判断，不烧 token）
> · 会发表情包、会搜图、会发语音，还能真唱两句
> · 私聊随时在，群聊按点上下班
>
> 开源（MIT），一键安装脚本，自己填个 QQ 号就能用：
> https://github.com/s1700884260/qq-bridge-fork

### C. 技术群 / 开发者（只讲实现）

> 分享一个 QQ ⇄ DeepSeek Harness 的桥接 fork：
> https://github.com/s1700884260/qq-bridge-fork
>
> 和上游最大的区别是**成本控制**：
> 1. 群消息先用本机 Ollama `qwen2.5:3b` 做 speak/skip 二分类，skip 的分支完全不进云端（40ms 级，带模型预热）
> 2. 会话上下文按轮数/长度轮换，新会话用摘要接续，避免每轮重发长上下文
> 3. 群聊按时间表静默（8:00–18:00 在岗），静默期直接不消费 token
>
> 另外内置了 Edge TTS 语音条、DiffSinger 真唱、表情包库与搜图。上述改动都在 `FORK.md` 里列了 diff 范围。

### 发帖注意

- **别发到不允许推广的群**；一次性发一两个地方就够，刷屏容易招反感。
- 帖子里的截图/视频按上面「录制前脱敏清单」处理。
- 有人问「要不要 API key / 花钱吗」：本地分流那步不花钱，模型本身走你自己的 DeepSeek API key，按官方价目表计费。
